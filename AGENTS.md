# Рабочие правила Mob Talk (для любого ИИ-агента)

Этот файл читают все агенты: Claude Code (через CLAUDE.md), opencode с Kimi, Codex, Cursor и другие.
Агент без нашей памяти проекта должен начать отсюда, затем прочитать:

1. docs/agents/project-rules.md — правила и решения Дмитрия (лицензии, стиль, запреты, инфраструктура).
2. docs/agents/coordination.md — как работать параллельно с другими агентами, карта веток и «горячие» файлы.
3. docs/agents/opencode-kimi.md — как запускать opencode/Kimi в отдельном worktree.
4. docs/HANDOFF.md — статус, пути, команды сборки и самотестов; docs/design.md — устройство мода.

## О проекте

Mob Talk — фановый Fabric-мод для Minecraft 1.21.1 (Java 21, Loom, Fabric API), GPL-3.0, некоммерческий.
Мобы и жители разговаривают голосом и текстом через LLM. Один jar (`environment: *`) работает и в одиночной
игре, и на выделенном сервере (админка в браузере, роли admin/streamer/player). Владелец — Дмитрий
(GitHub `BigZet`), общаться с ним по-русски.

- `src/main/java/io/github/mobtalk/` — общий и серверный код (`core/` — логика без Minecraft, `server/` — сервер
  и веб-админка), `src/client/java/...` — клиент (HUD, экраны F7/F9, самотест `SelfTest`), `src/test/java` — тесты.
- `src/main/resources/assets/mobtalk/lang/{ru_ru,en_us}.json` — строки, `data/mobtalk/` — worldgen и структуры.
- `scripts/` — PowerShell для Windows (сборка паков, Prism, самотесты, сервер), `tools/` — Python-генераторы
  (города, мебель, казино, бар), Whisper-сервер, `third_party/` — чужой код с лицензиями, `docker/` — сервер.

## Сборка и проверка

- Windows: `.\gradlew.bat test build`; если `build` падает по памяти в `remapSourcesJar`, то `.\gradlew.bat remapJar`.
- Linux/облако: `./gradlew test build --no-daemon --max-workers=2` (для облачного контейнера см. раздел
  «Облако» в docs/agents/project-rules.md — нужен init-скрипт с зеркалом Maven Central).
- Живые пробы LLM: `MOBTALK_LIVE=1` + тесты `*LiveProbeTest`; без ключа они пропускаются. TTS не вызывать.
- Самотест в игре (только Windows-ПК Дмитрия): `powershell -ExecutionPolicy Bypass -File scripts\run-selftest.ps1 [-Only <этап>]`,
  в конце `[selftest] ALL CHECKS PASSED`. Порядок и ограничения — docs/parallel-selftest.md и docs/pack.md.
- Применяйте минимальные проверки: одна сборка и тесты, относящиеся к новому сценарию.
- Не заявляйте о проверке микрофона или настоящей игры без фактического прогона; отличайте юнит-тест,
  самотест и живую пробу от ручной проверки Дмитрием.

## Жёсткие правила кода

- Секреты не попадают в git, логи, конфиг JSON и JAR (ключи только в DPAPI или переменных окружения).
- Не блокируйте игровой поток сетью, распознаванием, диском или микрофоном.
- Никогда не запрашивайте загрузку или генерацию чанков вне игрового потока и в задачах, которые могут
  выполняться при выходе: 1.21.1 навсегда виснет на «Saving worlds». Читайте чанки в тиках малыми порциями.
- Сбой LLM, TTS или Whisper никогда не ломает сцену: всегда есть запасной путь.
- Диалог отменяется при смене мира или цели, смерти или выгрузке моба.
- Запись микрофона только по удержанию кнопки; максимум 15 секунд, только клятва на свадьбе — до 120 (по умолчанию 60).
- Новое поведение настраивается в F7 (`MobTalkConfig`/`Tunables`) или F9 (права), с понятной подписью на русском.
- Новая логика — в новых классах; в общих файлах (`MobTalkConfig`, `Tunables`, `MobTalkMod`, `MobTalkClient`,
  `MobTalkSettingsScreen`, `SelfTest`, `MobTalkAdminSource`, lang json, `mobtalk.mixins.json`) только короткие точки подключения.
- Не меняйте соседние проекты (minecraft-parrot, divine-block, rusflora) из этого репозитория.

## Git

- Своя ветка и свой worktree на задачу, слияние в `main` только через PR. Прямо в `main` не коммитить.
- Не пушить, пока Дмитрий не попросит; GitHub-релизы не делать никогда без его слова.
- Коммиты на русском или английском, по одному смыслу на коммит; подпись агента в конце сообщения
  (например `Co-Authored-By: Kimi (opencode)` или строка, которую требует ваш инструмент).
- Чужие ветки (`claude/*` и других агентов) не трогать: не пушить в них, не переписывать историю.
  Подробности — docs/agents/coordination.md.
