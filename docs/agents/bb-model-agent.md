# Агент доработки модельек Blockbench (bb-model-dev + bb-model-critic)

Определения агентов: `.opencode/agents/bb-model-dev.md` (разработчик) и
`.opencode/agents/bb-model-critic.md` (критик) в этом репозитории. Промпты
агентов — на английском, с Дмитрием оба общаются по-русски. Изменения в промпты
— отдельным маленьким PR, как и в другие общие файлы.

## Модели

- Разработчик `bb-model-dev` — `zai-coding-plan/glm-5.3-flash#high` (быстрая,
  с глубоким размышлением).
- Критик `bb-model-critic` — `zai-coding-plan/glm-5.3#high` (reasoning high),
  только для чтения: правки, шелл и Code Mode у него запрещены.

## Как запускать

Новая сессия с агентом `bb-model-dev` (в OpenChamber — создать сессию с этим
агентом или выбрать его в TUI) и задание по-русски, например:

> Возьми `C:\...\apt_stool.bbmodel`, тип: только текстура, исходник сохраняем.
> Прокрась сиденье в тёмно-зелёный винил, сохрани стиль пака. Потом экспорт
> java_block json в такой-то путь.

Разработчик сам создаёт рабочую папку задачи, гоняет цикл и показывает галереи.

## Матрица задач (обязательный intake)

Тип: `TEXTURE_ONLY` (только текстура) | `GEOMETRY_ONLY` (только геометрия) |
`GEOMETRY_TEXTURE` (геометрия + доработка текстуры) | `FULL_REBUILD`
(полная переработка).

Влияние исходника: `KEEP` (исходник — база, меняем только запрошенное) |
`REFERENCE` (исходник — отправная точка, можно сильно перерабатывать) |
`SCRATCH` (с нуля, исходник только как ориентир размера/формата).

Если из задания не ясно, что выбирать — агент ОБЯЗАТЕЛЬНО спрашивает Дмитрия
карточками выбора, угадывать запрещено.

## Цикл (до 3 итераций)

1. Правки модели через blockbench-headless MCP (по умолчанию, атомарные
   ревизии) или blockbench-desktop (референсы в Copilot-панели, живое окно).
   `bbmodel_validate` после каждой пачки правок.
2. Рендер ракурсов `front / three-quarter / right / left / back / top`
   (орто, flat, 768px) в папку итерации.
3. Критик `bb-model-critic` (субагент) читает все PNG итерации и выносит
   `VERDICT: ACCEPT | REVISE` со списком артефактов и точными неразрушающими
   исправлениями.
4. Галерея openchamber со скриншотами итерации + ПОЛНЫЙ путь папки итерации
   в чате. По умолчанию агент ждёт слова Дмитрия («Дальше» или правки в поле
   заметки); по команде «без пауз» — гоняет итерации подряд.
5. Правки Дмитрия (меж- и послеитерационные) всегда поверх мнений критика.

Ранний выход — ACCEPT критика по всем моделям + подтверждение Дмитрия.
После 3-й итерации без приёмки — честный итог: что осталось, предложения
критика, ссылки bbmodel_web_url.

## Код за пределами модели

Геометрия, текстуры и анимации внутри `.bbmodel` — работа по модели. Всё
остальное — Java/JS кода мода, регистрация блоков/сущностей/предметов, спавн
и размещение модели в мире, взаимодействие с окружением, рендереры, подключение
анимаций в коде, скрипты паков — только с явного согласия Дмитрия: агент
останавливается и показывает карточку (какой код нужен, какие файлы, что
меняет в поведении). Пишет код только после «да»; решение фиксируется в
`brief.md` (`code: ask | auto-accept`).

Фразы «автоприём кода» / «код без апрува» снимают спрос до конца задачи:
агент доводит код сам, но по правилам репозитория (AGENTS.md,
docs/agents/project-rules.md — новая логика в новых классах, горячие файлы
минимально, настройка в F7/F9 с русской подписью), с минимальной проверкой
(одна сборка + профильные тесты) и перечисляет все изменения кода в отчётах
по итерациям и в итоговом.

  brief.md     класс задачи, требования, журнал правок Дмитрия
  orig\        нетронутые копии исходников
  before\      рендер «до» (three-quarter)

(java_block json, bedrock geometry, текстуры) — только по явно указанному пути.
