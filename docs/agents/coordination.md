# Параллельная работа нескольких агентов

С 26 октября 2026 над Mob Talk одновременно работают треды Claude (ветки `claude/*`) и другой агент
(Kimi через opencode). Цель — чтобы они не правили одно и то же и не ломали друг другу ветки.

## Правила

1. **Одна задача — одна ветка — один worktree.** Ветки другого агента называются `kimi/<коротко-о-задаче>`
   (или `<имя-агента>/...`). Worktree: `git worktree add ../mob-talk-kimi-<задача> -b kimi/<задача> origin/main`,
   чтобы не мешать чужому `git checkout` в общей папке `mob-talk`.
2. **Заявка до начала работы.** Задача считается занятой, когда на неё есть черновой PR (draft) в `main`
   с понятным названием, или Дмитрий явно отдал её агенту. Перед стартом посмотрите открытые PR и таблицу ниже:
   если задача или область уже чья-то — спросите Дмитрия.
3. **Чужие ветки только читать.** В `claude/*` не пушить, не ребейзить, не мержить в них. Нужен код из чужой
   ветки — дождитесь её слияния в `main` или попросите Дмитрия.
4. **В `main` — только через PR**, по одному. Перед PR влейте свежий `main` в свою ветку
   (`git merge origin/main`, без rebase опубликованной ветки) и прогоните тесты.
5. **Горячие файлы трогать минимально** (ниже). В них — одна-две строки подключения, вся логика в новых классах
   и новых файлах ресурсов. При конфликте в этих файлах объединяйте обе стороны, ничего не выкидывая.
6. **Свои ресурсы.** Новые ключи lang — с префиксом своей фичи (`mobtalk.<фича>.*`), новые звуки и текстуры —
   в своей подпапке, свой этап самотеста (`-Only <фича>`), свои порты сервера и Whisper.
7. **Правила проекта общие.** AGENTS.md и docs/agents/project-rules.md действуют для всех. Изменения в них
   и в этой карте — отдельным маленьким PR.

## Что лучше отдавать второму агенту

Хорошо подходят задачи с чёткими границами, которые почти не трогают области из таблицы:

- исправления багов из docs/HANDOFF.md §5 (например, книга на аналое в церкви — это репозиторий divine-block);
- тесты на непокрытый код в `core/` (чистая Java без Minecraft, легко проверить `gradlew test`);
- веб-админка (`docs/admin-web`, `server/web`), кроме `MobTalkAdminSource` — его правьте точечно;
- инструменты в `tools/` и скрипты в `scripts/`, документация;
- новая отдельная фича в своём пакете (`io.github.mobtalk.<фича>`), подключённая одной строкой.

Плохо подходят: города, мебель, магазины, чиновники (это одна большая связка веток), а также общие
промпты (`MobPrompt`, `PromptTexts`), пока там работают треды Claude.
