# Голосовой торг с жителями — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Выполнять без дополнительных остановок: пользователь явно попросил проработать механику и реализовать её.

**Goal:** Живой торг голосом по настоящей выбранной сделке жителя с небольшой одноразовой уступкой.
**Architecture:** Whisper и LLM переиспользуются. LLM возвращает намерение переговоров; сервер проверяет цену, состояние и оплату. Временная уступка меняет только первую входную стопку; обычное торговое окно отвечает за передачу предметов.
**Tech Stack:** Fabric/Minecraft 1.21.1, Java 21, существующие OpenRouter/Whisper и ConversationStore.
**Spec:** Правила ниже, уточнённые пользователем 15 октября 2026: торг голосом; уменьшать можно и количество предметов за изумруд.

## Правила

- Открыто окно именно этого взрослого жителя; выбрана реальная доступная строка. Никаких придуманных товаров.
- Уступка максимум `min(3, floor(текущаяЦена/10), текущаяЦена-ceil(базоваяЦена*0.9))` единиц первого входного предмета.
- При отношении 0..29 максимум одна единица, от 30 доступен полный предел; отрицательное отношение исключает уступку.
- Количество результата, второй ингредиент, использования/пополнение и опыт остаются ванильными. Правило одинаково для палок и изумрудов.
- До трёх предложений/контрпредложений. Игрок подтверждает предложение голосом. Действие цены — один оплаченный обмен, включая Shift-клик.
- Предложение действует 6000 игровых тиков от начала, без продления при согласии/закрытии окна. Новые переговоры с тем же жителем и игроком — через 24000 тиков. Состояние сохраняется в мире.
- Плохие отношения, исчерпанная строка или цена без целочисленной возможности уступки не начинают попытку.
- При изменении товара/зачарования/цены, ударе или отключении мода уступка снимается. Закрытие окна снимает только временный ценовой слой, сохраняя договорённость до исходного срока.
- Никаких сетевых/микрофонных/дисковых операций на игровом потоке; никакого нового доступа к секретам.

## Задачи

- [x] Core: BargainIntent, Bargaining, сохранение сессии через ConversationStore; целевые тесты округления, ванильного пола, подтверждения, трёх раундов, срока и однократности.
- [x] LLM: структурированное намерение и контекст реальной цены; совместимые Reply/Answer и HTTP-фикстуры.
- [x] Игра: выбранная строка, временный specialPrice, проверка до изъятия результата, расход после успешной оплаты, восстановление и синхронизация.
- [x] Клиент: удержание выбранной клавиши в MerchantScreen, реальный собеседник/customer, отмена при смене окна.
- [x] Интеграция: регистрация mixins, версия и краткая инструкция; итоговая сборка с целевыми тестами, короткий статический проход по изменениям.

## Review Focus

Shift-покупка расходует уступку один раз; устаревшее окно не выдаёт бесплатный результат; native reputation/Hero/Demand не затираются; неверный покупатель не получает уступку; загрузка мира и закрытие диалога не сбрасывают срок/кулдаун.

## Проверка 0.2.4

Сборка и целевые Bargaining/Store/ConversationEngine/Whisper/Combat тесты прошли. Пойманные ими проблемы сохранения нового состояния и озвучивания отклонённой цены исправлены. Один статический проход проверил путь выдачи товара, Shift-клик и временный ценовой слой.

Два настоящих текстовых запроса через `google/gemini-3.1-flash-lite`: предложение 29 палок вместо 32 и распознавание согласия; серверные чистые правила подтвердили ACCEPTED/29. Это синтетический снимок торгового окна, а не игровой прогон и не проверка микрофона.

Текущая пользовательская `google/gemma-4-31b-it:free` сначала вернула HTTP 404 для strict schema. Добавлен однократный переход на JSON object с той же локальной проверкой ответа и общей временной границей; следующий живой запрос упёрся в HTTP 429. Выбранная модель в настройках не изменена. Массовых проб и повторов при 429 нет.

Новые mixins и голосовую клавишу в настоящем MerchantScreen в этой сессии не запускали; для этого нужен короткий пользовательский игровой прогон после перезапуска.

## Исправление 0.2.5

Пользователь сообщил об ошибке «OpenRouter LLM вернул неверный ответ» при торге. С текущей пользовательской Gemini 2.5 Flash Lite воспроизведён корректный JSON, в котором реплика отказывает в скидке, а намерение OFFER пытается назначить недоступную уступку. Прежняя проверка превращала такое несоответствие в общую ошибку формата.

Контекст и JSON-схема теперь перечисляют разрешённые сейчас шаги, учитывая окончательную цену, принятое предложение, срок и перерыв. Неверное намерение получает одну исправительную генерацию в общем таймауте. Отказ без открытого окна обрабатывается как обычная беседа; неиспользуемый discount при подтверждении не мешает принять сохранённую цену. История, резюме и социальные изменения сохраняются после успешного применения ответа игрой.

57 целевых тестов Bargaining/Store/ConversationEngine/ConversationDelivery прошли, JAR 0.2.5 собран. Повтор исходного текстового сценария через текущую Gemini 2.5 Flash Lite успешно вернул NONE и отказ без скидки. Игровое окно и микрофон в этом исправлении не проверялись.
