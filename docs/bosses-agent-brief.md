# Brief: implementing sacred bosses (shared by every boss worker)

Mod: «Божественный блок», a Fabric mod for Minecraft 1.21.1, yarn 1.21.1+build.3, Java 21, GPL-3.0. It's a single-player client mod, and
everything runs on the integrated server. The style is dark Russian Orthodox and biblical: black, old gold, candlelight, bronze, bone, fire.
All models and textures are original. They're drawn by code in `scripts/bosses/*.py`, so outside art and ripped models are not allowed.
Mechanics must be clean-room: describe-and-reimplement only, with no code copied from mods that have ARR licences.

## The framework is already there (read these first)
- `src/main/java/io/github/divineblock/boss/SacredBoss.java`: the base class. It provides the boss bar, power 1..5, the difficulty
  setting, phases by health (`phaseCount()`, default 3; `onPhase(n)`), an attack timer (`attack(target)` returns the ticks until the next
  attack), an ultimate timer (`ultimate(target)` MUST call `castUltimate(warning, strike)`, which shows a title 3 s ahead), and
  `cast(name, warnTicks, holdStill, warning, strike)`, which telegraphs an ordinary attack. It also has melee (`meleeReach()`,
  `meleeDamage()`), `pursue(target)` for movement, `hurt(victim, base)`, which ALWAYS caps a hit at 45% of max health,
  `push(victim, from, strength, lift)`, `victims(center, radius)`, `particles(...)` (visible far away), `sound(...)`, `mayBreakBlocks()`
  (the settings toggle plus mobGriefing) and `debug(line)`, which logs only in debug mode. `onDefeated()` runs on death.
  `theme()` names the chant that loops during the fight.
- `Hazards.java`, reached through the `hazards` field: `orb`, `ring` (on the ground, low enough to jump over), `zone` (a marked circle,
  then a strike), `beam` (a dotted line first, then a burning line), `later` and `repeat`. All of them tick with the boss and are cleared on death.
- `BossEffects.java`: the afflictions are ALREADY registered (`VOW_OF_SILENCE, RINGING, SCORCH, GAZE, PANIKHIDA, DEPTHS, DUST, STUN,
  FAMINE, FIRSTBORN_MARK, EXILE, MARK_OF_BEAST, CONFUSION`). Apply one with `BossEffects.afflict(victim, effect, ticks)`. Shared rules
  that already work: VOW (food, drink and totem blocked, prayer blocked), SCORCH (heal becomes damage), PANIKHIDA (max health drain,
  `BossEffects.liftAll(server)`), DUST (no jumping, through a mixin), DEPTHS (sinking in water, client side in BossClient), MARK_OF_BEAST
  (no trading), RINGING and GAZE (client side, in BossClient and the mixins). Every other affliction's rule is YOURS to implement in
  `XEntity.registerHooks()` (server events) and/or `XModel.registerClient()` (client events). Both are empty stubs that already get called.
- `SchemnikEntity.java`, `SchemnikModel.java` and `scripts/bosses/schemnik.py` are the finished reference boss. Copy their structure.
- `DivineBosses.java` is the registry and API. Entity dimensions and base health for every boss are there, and you may change ONLY your
  own boss's line or lines if the size needs it. Loot tables, relic items, names (lang), effect icons and the seal block are already
  generated by `scripts/bosses/resources.py`. Don't touch them.
- Models: write `scripts/bosses/<id>.py` using `boxtex.py` (`Part`, `Box`, styles `cloth/metal/solid/fire/candle/gold/eyes_face`,
  `draw_cross`, or your own style functions). Run `python scripts/bosses/<id>.py` from the repo root. It generates
  `src/client/java/.../client/boss/<Name>ModelData.java` plus `textures/entity/boss/<id>.png` and `<id>_glow.png` (the glow texture is
  drawn at full brightness, which suits eyes, flames and halos). Model space: y points down, the ground is y=24, the boss faces -Z,
  and 16 units = 1 block. Fit the entity's hitbox in DivineBosses, or scale it with the renderer's scale argument (in BossClient, only
  on your own line). Then animate in `<Name>Model.animate(...)` by part name. `boss.castState()` is 0 idle, 1 casting or 2 ult;
  `boss.syncedPhase()` gives the phase. Use 128x128 textures, or 256 when the model is huge.
- Commands for testing in game: `/divineblock boss <id> [power]`, `/divineblock boss ult`, `/divineblock boss clear`.

## Rules
- Telegraph everything. Each attack gets at least ~0.75 s of visible warning (particles plus sound), and the ultimate goes through
  `castUltimate`. No unfair one-shots: use `hurt()`, which caps damage. Bosses have 2–3 phases (Horsemen: 4) and 3+ distinct attacks.
- Block changes (breaking, fire, building) happen only when `mayBreakBlocks()` is true. Otherwise there must be a non-destructive
  fallback for the same mechanic.
- Never block the server thread with network or disk work. Bosses use no LLM or TTS at all.
- Debug output only through `debug()`.
- Comments should be short, the house style is plain English javadoc on classes and methods, and naming follows the existing code.
- Edit ONLY your own boss files: `boss/<Name>Entity.java`, any new `boss/<Name>*.java`, `client/boss/<Name>Model*.java`, any new
  `client/boss/<Name>*.java`, `scripts/bosses/<id>.py` and your textures. If you need a mixin, add a NEW file under
  `src/main/java/io/github/divineblock/mixin/` or `src/client/java/io/github/divineblock/client/mixin/` and add exactly one entry to
  the matching `*.mixins.json`. Do not edit SacredBoss, Hazards, BossEffects, BossKind, BossClient (except your renderer line),
  DivineConfig, Prayers or any other shared class. If you truly need a framework change, implement it locally in your own class instead,
  or describe it in your final report.
- Verify the APIs against 1.21.1 yarn. Named jars are under `%USERPROFILE%\.gradle\caches\fabric-loom\minecraftMaven\net\minecraft\`
  (minecraft-common-... and minecraft-clientonly-...). Use `javap -cp <jar> -p <class>` when you aren't sure about a name.
- Build in YOUR worktree only: `.\gradlew.bat build -x test` (PowerShell) must succeed. Do NOT launch Minecraft or Prism, and do NOT
  touch the Prism instances. The coordinator tests in the game afterwards.
- When it builds, commit to your branch (`git add -A; git commit`). Write the message in Russian, in the style of `git log`, and end it
  with the line `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`. Never push, and never touch other branches or worktrees.
- Bash heredocs with apostrophes break in this environment. Write files with the file tools and run python scripts from files.
- Final report (short): what each boss does (attacks, ult, affliction, phases), the files changed, anything left unfinished or
  uncertain, and any framework change you wished for.
