## 1. Viewer Parrots на выделенном сервере

**Факты** (исходники `minecraft-parrot` @ `303597b`, версия 1.2.1; jar в паке `viewerparrots-1.2.1.jar` проверен `javap`, гейт тот же):

- Команды регистрируются в `command/ViewerParrotCommands.register()`: корень `CommandManager.literal("viewerparrot")` и
  `dispatcher.register(literal("vp").redirect(registered))`. Подкоманды: `help`, `twitch [status|connect|disconnect]`, `streamer`,
  `setstreamer <player>`, `create`, `remove`, `rename`, `trait`, `respawn`, `reconcile`, `info`, `list`, игровые действия
  (`come`, `follow`, `free`, `freefollow`, `view`, `deview`, `arm`, `dearm`, `sit`, `dance`, `spin`, `scream`, `say`, `love`, `hat`,
  `dehat`, `color`, `name`, `emote`, `fight`, `accept`, `decline`, `exp`, `roulette`), `save`, `reload`, `status`.
- Права уже свои: каждый узел `.requires(allowed(source, action))` → `PermissionService.isAllowed`. **Уровень 0 не получает ни одной
  команды** (явная проверка `permissionLevel() == 0 → false`), остальные — по `controlLevel`/`adminLevel` из `viewerparrots.json`
  (по умолчанию 2 и 3). Уровень берётся из ванильного `hasPermissionLevel`, LuckPerms/fabric-permissions-api не используется.
- Сеть мода: вход — `ClientCompatibility` (login query, проверка версии клиента), игра — только S2C: `RoulettePayload`,
  `SpeechAudioPayload` (озвучка попугаев чанками всем в мире). **C2S-пакетов нет.**
- Twitch: `twitch/TwitchIrcClient` (IRC по TLS, `CAP REQ :twitch.tv/tags twitch.tv/commands`, только чтение: шлёт `PASS/NICK/JOIN/PONG`,
  `PRIVMSG` не отправляет). Гостевой режим — анонимный логин `justinfan<число>` без токена, роли (mod/vip/sub) всё равно приходят в тегах.
  Мост `TwitchChatBridge` живёт **внутри серверной части** (`src/main`), очередь команд разбирается в `tick` сервера и уходит в
  `context.api().submit(request, ActorContext.twitch(...))`.
- `TwitchChatBridge.onWorldOpened`: `if (!context.server().isDedicated()) active = new TwitchChatBridge(context);` — на выделенном
  сервере моста нет, `/vp twitch` отвечает «Twitch доступен в открытом одиночном мире».
- Панель F8 (`client/menu/ControlPanelScreen` → `control/ControlPanelService`) работает вызовами статических методов в той же JVM
  (`ServerContext.current()`), а на выделенном сервере каждый её метод возвращает «Нужен одиночный мир». С клиента, подключённого к
  выделенному серверу, F8 показывает «Мир не открыт»: управлять попугаями и Twitch оттуда нельзя.
- Вход в Twitch (device flow, `auth/TwitchAuthService`) и ключ OpenRouter хранятся у того, где запущен мод: `LocalSecretStore`
  (DPAPI на Windows, открытый файл `config/viewerparrots-*.credentials` на Linux), ключ OpenRouter ещё из `OPENROUTER_API_KEY`.
- `ControlPanelService.initialize` вызывается и в `ViewerParrotsMod.onInitialize` (сервер), так что настройки
  `config/viewerparrots-settings.json` на выделенном сервере читаются.

**Вывод.** Попугаи, их поведение, озвучка и команды `/vp` на выделенном сервере работают (весь мир — `ServerContext` по
`SERVER_STARTED`), а Twitch и панель F8 — нет. Пункт плана «стример подключает Twitch на своём клиенте через F8» без изменения
Viewer Parrots невозможен: клиент стримера не может передать токен или команды серверу, а Mob Talk не должен зависеть от jar Viewer Parrots.

**Решение.** 22.10 Дмитрий ответил «Ок» на рекомендацию «гость» (п. 1 ниже). Правка — отдельная задача в `minecraft-parrot`,
из этого репозитория его не меняем; до неё Twitch работает только в одиночке.

**Рекомендация (правка проекта `minecraft-parrot`).**
1. Минимальная правка Viewer Parrots: разрешить мост на выделенном сервере **только в гостевом режиме**. Сервер читает чат канала
   анонимно (`justinfan`), токен Twitch на сервер не попадает вовсе, роли зрителей приходят тегами. Канал и `autoConnect` — в
   `config/viewerparrots-settings.json` на сервере (поле `twitch.channel`, `guest=true`), управление — `/vp twitch connect|status|disconnect`.
   Это закрывает требование «коды Twitch никому не передаются» лучше, чем device flow на клиенте.
2. Вход по аккаунту Twitch (не гостевой) на выделенном сервере не нужен: мост только читает чат.
3. Панель F8 на выделенном сервере — отдельная работа в Viewer Parrots (пакеты запрос/ответ); в первую версию не брать,
   стримеру хватит канала в админке и `/vp twitch`.

**Для C (фильтр команд).** Корни для `Permissions.mayRun`: `viewerparrot`, `vp`, `divineblock`, `mobtalk`. Игроку (`PLAYER`, уровень 0)
Viewer Parrots и так ничего не даёт. Стример без оп-уровня тоже не получит `/vp`: мод проверяет ванильный `hasPermissionLevel(2)`, и
фильтр Mob Talk может только **убрать** команды, не выдать. Для первой версии: `/vp` — только `ADMIN` (оператор ≥ 3), стример
управляет попугаями через Twitch-чат; админка шлёт `/vp ...` через консоль сервера. Давать стримеру `op 2` не стоит — откроются
ванильные `/tp`, `/give` и т. п. Фильтр делать в `CommandRegistrationCallback` после регистрации всех модов (или миксином в
`CommandManager.sendCommandTree` + проверка в `execute`), по первому литералу; redirect `vp` фильтровать отдельно.

## 2. OpenRouter STT

**Как проверено.** Живые запросы 22.10 с ключом из DPAPI (`%LOCALAPPDATA%\MobTalk\openrouter-key.dpapi`, ключ только в окружении
дочернего процесса, в логи не попадал). 8 фраз из `%LOCALAPPDATA%\MobTalk\train\dataset\val.jsonl` (голос Дмитрия в игре, WAV 16 кГц
моно, 2–12 с, 38,8 с в сумме; пять с игровыми словами: крипер, скелет, зомби, житель, Майнкрафт). В `selftest-fixtures` из брифа
лежат только две `.pcm` без текста, поэтому фразы взяты из набора дообучения Whisper.

**Важно про эталон.** Тексты в `val.jsonl` — разметка самим `large-v3` (с ручной проверкой части), поэтому WER локального `large-v3`
занижен, а у облачных моделей завышен там, где эталон сам ошибся (например «меня много убивают» — пять моделей из десяти
слышат «меня мобы убивают», «некоторая девица» — большинство слышит «некоторое дельце»). Колонка «на глаз» учитывает это.

**Запрос**, который работает (документации на сайте нет, формат найден пробой):

```http
POST https://openrouter.ai/api/v1/audio/transcriptions
Authorization: Bearer <ключ>
Content-Type: application/json

{"model": "mistralai/voxtral-mini-transcribe-3-0", "input_audio": {"data": "<base64>", "format": "wav"}, "language": "ru"}
```

Ответ: `{"text": "...", "usage": {"seconds": 8, "cost": 0.0008}}`. Оплата за **целые секунды с округлением вверх** (7,24 с → 8 с),
`usage.cost` в долларах — его и писать в `PlayerBudget.charge`. Форматы `wav`, `mp3`, `ogg` (Opus) приняты.

**Рекомендация для B.**
- Модель по умолчанию `mistralai/voxtral-mini-transcribe-3-0` (≈ $0,00026 за фразу 5 с, ≈ $0,0035 за минуту речи); запасная
  `openai/whisper-large-v3` (в 7 раз дешевле, хуже на игровых словах). Обе — в `ServerConfig`, админ меняет без пересборки.
- Не использовать `gpt-4o-*-transcribe` (меняют язык даже с `"language":"ru"`), `qwen3-asr` (таймауты), MP3 (хуже WAV и Opus).
- Свой таймаут 8 с и одна повторная попытка на запасной модели: у voxtral был выброс 25 с на одном запросе из 40.
- Формат: **WAV 16 кГц моно** — так пишет микрофон сейчас, кодировщик не нужен, лучшая точность; 15 с = 480 КБ, помещается в один пакет
  (раздел 6). Для клятвы 120 с (3,84 МБ) — чанки или Opus; Opus в Java — библиотека Concentus (чистая Java, BSD), это решение B.
- Подсказки (`hints`, слова мира): поле `prompt` в этом эндпоинте не проверено; первая версия без него.
- Локальный helper у игрока с GPU по-прежнему лучше всех (0,5 с, бесплатно); на CPU — только `small`/дообученная `mobtalk-small-ru`
  (1,8 с, WER 0,20), `large-v3` на CPU слишком медленный. Значит, порядок `local` → `server` из плана верен, но `local` на CPU стоит
  предлагать только с `small`.

## 5. Священные боссы

**Факт** (`divine-block` `boss/DivineBosses.java`, `BossPunishment.java`, `BossSealBlockEntity.java`, `BossCommands.java`, чтение кода):
единственная точка появления `DivineBosses.spawn(kind, world, pos, power, target)` не проверяет, есть ли уже живой босс. Пути, которые
её зовут: кара «святые стражи» (`BossPunishment.summon`, по одной на каждого грешника), печати в постройках
(`BossSealBlockEntity.wake`, при приближении игрока), команда `/divineblock boss`. Есть только поиск `near(world, pos, radius)` для
`ult` и `clear`. «Бог с булавой» (`GodWrath`) — по одному на игрока (повторный вызов для того же игрока заменяет первый), но для разных
игроков их может быть несколько. Отключённый в настройках босс приходит ванильным мобом (`fallback`) — тоже без ограничения.

**Вывод.** С 6 игроками одновременно возможны несколько священных боссов (кары на разных игроков, печати в разных постройках).

**Рекомендация для D.** Ограничение «один священный босс на мир» в `DivineBosses.spawn` (одна точка на всех): учёт живого босса в
`PersistentState` мира по UUID (чтобы босс в выгруженном чанке тоже считался), снимать при смерти/деспавне. При занятом месте:
кара — заменить другим наказанием из той же группы; печать — не просыпаться, пока босс жив; команда админа — с флагом принудительно.
«Бог с булавой» — оставить по одному на игрока (кары бьют всех), но ограничить общим числом, например 3 одновременно.

## 6. Лимиты сети в 1.21.1

**Факты** (байткод `minecraft-merged-1.21.1` yarn build.3 и `fabric-networking-api-v1 4.3.1` из Fabric API 0.116.17, как в паке, `javap`):

| Где | Предел |
| --- | --- |
| `CustomPayloadC2SPacket.MAX_PAYLOAD_SIZE` | 32 767 байт — но применяется только к `UnknownCustomPayload` (канал, который сервер не зарегистрировал) |
| `CustomPayloadS2CPacket.MAX_PAYLOAD_SIZE` | 1 048 576 байт — то же, только для незарегистрированных |
| Зарегистрированный payload (`PayloadTypeRegistry.playC2S/playS2C`) | своим кодеком без проверки размера; Fabric API 4.3.1 размер не ограничивает и пакеты не режет |
| `SplitterHandler` / `SizePrepender` | длина кадра — VarInt не шире 3 байт → **≤ 2 097 151 байт после сжатия** |
| `PacketInflater.MAXIMUM_PACKET_SIZE` | **≤ 8 388 608 байт после распаковки** |
| `PacketCodecs.BYTE_ARRAY` | без предела; `PacketCodecs.byteArray(max)` — с пределом |

Размеры аудио (замер ffmpeg на 38,8 с речи): WAV 16 кГц моно 16 бит — 32 000 байт/с, **15 с = 480 КБ**, 120 с = 3,84 МБ (WAV почти не
сжимается zlib); Opus 24 кбит/с — 3 060 байт/с, 15 с ≈ 46 КБ, 120 с ≈ 368 КБ; MP3 32 кбит/с — 4 090 байт/с, 15 с ≈ 61 КБ.

**Рекомендация для S1/A и B.**
- `TalkAudioC2S` с WAV до 15 с (480 КБ) проходит одним пакетом. Предел в кодеке задать явно: `PacketCodecs.byteArray(1_000_000)`,
  на сервере дополнительно отбрасывать больше `seconds × 32 000 + 1 КБ` и чаще одного пакета на игрока в 2 с.
- Клятва 120 с: WAV одним пакетом не пройдёт (3,84 МБ > 2 МиБ кадра). Либо чанки по 512 КБ (`TalkAudioChunkC2S index/count`), либо
  Opus — тогда 368 КБ одним пакетом.
- `TalkTextC2S.picture` (JPEG ≤ 200 КБ) и `SpeechClipS2C` (чанки ≤ 512 КБ) в пределах; цифра «лимит payload 1 МБ» в разделе 12.1 плана
  верна только для незарегистрированных каналов, реальный предел — 2 МиБ кадра.
- Не проверено живым соединением: игра не запускалась. Проверка — тест кодека в `src/test` и самотест G с 15-секундной фразой.

## 3. WATERFrAMES на сервере

**Проверено без клиента.** Выделенный сервер из пункта 4 с jar из пака: `waterframes-FABRIC-mc1.21.1-v2.1.22`,
`watermedia-2.1.37`, `watermedia_youtube_plugin-2.1.2`, `CreativeCore_FABRIC_v2.13.48_mc1.21.1`, `watervision-FB-mc1.21.1-v0.1.0-alpha`
плюс Fabric API 0.116.17. Сервер стартовал за 1,8 с, в журнале `Running WATERFrAMES v2.1.22` и датапак `waterframes`, ошибок и
исключений нет; WaterMedia на сервере нативные библиотеки не грузит и ничего не скачивает. У всех пяти jar `environment: "*"`,
зависимости: WATERFrAMES → CreativeCore ≥ 2.13.11, WaterVision и YouTube-плагин → WaterMedia ≥ 2.1.30/2.1.37.

**Проверено с клиентом** (22.10, разрешение Дмитрия): одноразовая копия `mob-talk-pack` (`t-wf-*`, моды, которых нет на сервере,
выключены), `prismlauncher --launch <копия> --server 127.0.0.1:25599`, сервер в офлайн-режиме. Через RCON: платформа на y=199,
`setblock 6 201 10 waterframes:big_tv[facing=north,attached_face=down]`, `/waterframes edit 6 201 10 url <ссылка>`.
- Команда `/waterframes edit` выполняется на сервере, ссылка доходит до клиента; клиент сам грузит VLC 3.0.18 из кэша WaterMedia
  и ролик с YouTube. Через ~40 с на экране идёт видео (скриншот окна), сервер получил длину ролика (`tick_max: 12691`, ~10,5 мин)
  и ведёт `tick` — позиция воспроизведения общая для всех игроков.
- Нагрузка на сервер во время ролика: 6,7 мс на тик (P99 12 мс) — видео серверу ничего не стоит.
- Прямой эфир-запись `jfKfPfyJRdk` не играет («This live stream recording is not available», ошибка YouTube, не сервера);
  обычный ролик `aqz-KE-bpKQ` — играет.
- Выход: `kick` с сервера, потом закрытие окна — игра закрылась сама за ~6 с, краш-отчётов нет. В журнале клиента три
  `GL_INVALID_OPERATION/VALUE` от текстуры видео (были и в одиночке, на игру не влияют).

**Рекомендация для E.** На сервер ставить все пять jar (у сервера должен быть тот же набор, иначе блоки экрана не синхронизируются);
видео декодирует только клиент, поэтому нагрузки на сервер от роликов нет.

## 4. Борщевик под нагрузкой

**Как проверено.** Выделенный сервер Fabric 1.21.1 (loader 0.19.5) в одноразовой папке, моды `fabric-api 0.116.17`, `rusflora-0.1.0`
из пака и spark; `simulation-distance=10`. Шесть «игроков» — шесть зон `/forceload` по 21×21 чанк (441, как у игрока с
дальностью 10) в равнинах и лесу, всего 2 646 чанков. Естественных очагов в этих зонах почти нет (у `hogweed_plains` редкость
1/1280 чанков), поэтому худший случай задан руками: 215 очагов `place feature rusflora:hogweed_patch` сеткой 48 блоков, затем
`/tick sprint 48000` (два игровых дня), чтобы заросли разрослись до своих пределов (`maxPlantsPerChunk=48`, `maxPlantsPerRegion=400`).
Профиль — JFR 120 с днём (борщевик растёт только днём), доля сэмплов потока `Server thread` с кадрами `io.github.rusflora`.
Spark стоял, но его `profiler` выгружает отчёт на внешний сайт, поэтому профиль снят JFR локально.

| Состояние | Средний тик | Доля `rusflora` в потоке сервера |
| --- | --- | --- |
| Свежий мир, без очагов | 10,7 мс (P95 14,3) | 0 из 2 449 сэмплов |
| 215 очагов после двух дней роста | 10,8–16,5 мс (P95 22,1) | 7 из 2 229 = **0,31 %** (6 — `CowEatHogweedGoal.canStart`, 1 — `HogweedBlock.randomTick`) |
| `tick sprint` 48 000 тиков с ростом | 8,2 мс на тик | — |

**Вывод.** Борщевик занимает около 0,3 % времени тика даже при плотности в сотню раз выше естественной, порог 5 % из брифа далеко.
Случайный тик есть только у корня (`hasRandomTicks` при `PART == 0`), подсчёт зарослей кэшируется по чанку раз в минуту, а чанк без
борщевика отвечает по палитре секций. Заметнее всего не сам борщевик, а цель коров `CowEatHogweedGoal` (обход секций вокруг).

**Рекомендация.** Бюджет блоков за тик в `rusflora` не нужен, ветку `bigzet/tick-budget` не заводил. Если на живом сервере в
`spark` появится `CowEatHogweedGoal`, проще реже запускать её проверку (раз в 40–60 тиков), чем ограничивать рост.
